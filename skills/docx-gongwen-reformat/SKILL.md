# 公文格式全文重排（docx）

## 适用场景

- 手上有一份内容已定稿、但版式是"办公默认样式"（如正文 8pt 微软雅黑、深蓝色标题、无首行缩进、无页码、无分页）的 .docx 长文档，要**全文重排**为规范的建议稿／公文版式。
- 只改版式，**不改一个字的内容**。

不适用：局部内容修订（用 `docx-surgical-revision`）；从零生成文档（用 tencent-docx 的 HTML→DOCX 流程）。

## 环境（本机）

- 读改 docx 用带 python-docx 的解释器：
  `C:/Users/foofi/.workbuddy/binaries/python/envs/html-to-docx/Scripts/python.exe`
  （托管版 python 3.13.12 **没有** docx 模块）
- Bash 每条命令开头必须加：`export PATH="/usr/bin:/bin:/mingw64/bin:$PATH"`
- 脚本一律 Write 成 .py 再执行，**不要用 heredoc**（本机 shell 包装下会解析异常）。
- **本机没有 LibreOffice／Word**，无法渲染验证 → 用 `zipfile.testzip()` ＋ lxml 全 XML 解析 ＋ 子元素顺序校验替代。

## 默认版式规格（可在脚本顶部常量改）

| 元素 | 规格 |
|---|---|
| 页面 | A4 21×29.7 cm；页边距 上3.7／下3.5／左2.8／右2.6 cm |
| 一级标题（内容提要／编制说明／一—七／附录A—F） | 黑体**三号**（16pt），首行缩进2字符，**另起一页**，段前12磅段后6磅 |
| 二级标题（（一）（二）…） | 黑体**四号**（14pt），首行缩进2字符 |
| 三级标题（"1. 2."／"第N轮"） | 黑体**小四**（12pt），首行缩进2字符 |
| 正文 | 宋体**小四**（12pt）＋**1.5倍行距**＋首行缩进2字符＋两端对齐；西文与数字 Times New Roman |
| 表格 | 宋体**五号**（10.5pt）、表头行加粗居中、单元格垂直居中、单倍行距、首行跨页重复 |
| 表题注（以"表"开头） | 黑体五号居中，`keepNext` 防止与表分离 |
| 表说明／表前导语（"说明："/"注："） | 宋体五号、**顶格**、两端对齐 |
| 目录标题 | 黑体二号居中；目录条目 宋体小四、顶格、左对齐 |
| 页码 | 末节页脚居中 PAGE 域；首节（封面）不编号 |
| 字符颜色 | 全稿统一 `000000` |

字号换算：`w:sz` 是**半磅**——五号=21、小四=24、四号=28、三号=32、二号=44、一号=52。
行距 `w:line="360" w:lineRule="auto"` ＝ 1.5 倍。
首行缩进同时写 `w:firstLineChars="200"` 与 `w:firstLine`（＝2×字号pt×20 缇）。

## 三步流程

### 1. 版式勘察（先摸清底数，不要直接动手）

必查六项，写成一次性脚本输出：

1. 节数与每节页面尺寸／页边距／页眉页脚；`sectPr` 落在哪一段（分节位置＝封面到哪结束）。
2. 样式分布（Normal／Heading N／List Bullet／List Number 各多少）。
3. **全部 Heading 段落清单**（序号｜样式｜文本），据此确定一级／二级标题的真实集合。
   —— 别只信样式名：本机曾见"附录F"是 Normal、"表E-1"却是 Heading 3。
4. 目录区间：`目录` 段的位置、目录条目是**纯文本**还是 `w:hyperlink`。
5. 表格清单：逐表 `ncol` ＋**紧前那段文本**（题注）＋首行内容；单元格底纹、边框是否统一。
6. `w:pageBreakBefore`／`w:numPr`／空段落 分布。

### 2. 内容增补与排版分两个脚本，顺序固定

- `gongwen_format.py <doc.docx>` —— 套版式。
- `normalize_ooxml.py <doc.docx>` —— 收尾（**必须跑**，见下）。

若同时还要做内容增补（加口径注、加附录条目、同步计数），**增补脚本务必先 `shutil.copy2(SRC, DST)` 再从 SRC 重做**，
这样脚本可安全重入；排版脚本就地改写，所以每次改完增补都要"重跑增补 → 再跑排版 → 再跑收尾"。

### 3. 三级校验（缺一不可）

1. **内容零丢失**：以源文档为基准，逐段落取前 20 字、逐单元格取前 18 字，必须在成品全文里命中。
   同时比对字符总数（只改版式则字符数必须**完全一致**）。
2. **格式落地**：抽样打印 `pPr`（firstLineChars／line／jc／pageBreakBefore／keepNext）与
   `rPr`（rFonts.eastAsia／ascii／sz／color／b）。再逐项统计：分页一级标题数、表头行数、
   页脚 PAGE 域、页面尺寸、颜色分布（应只剩 `000000`）。
3. **结构合规**：`normalize_ooxml.py --check-only` 应报 0 处违规；`zipfile.testzip()` 为 None。

## 五个必踩的坑

| 坑 | 现象 | 处置 |
|---|---|---|
| **目录条目在 `w:hyperlink` 里** | 目录字号／颜色没改到，`p.runs` 是空的 | 自建 `allruns(p)`＝`p.runs` ＋ `p.findall(w:hyperlink)/w:r`，遍历必须用它 |
| **顺序插入不重定位已存在元素** | 原稿自带的 `w:spacing`/`w:ind`/`w:jc` 顺序不合规残留（本机一份稿自带 2043 处） | 收尾跑 `normalize_ooxml.py` 全量重排，`check-only` 归零才算过 |
| **按样式名判层级** | "附录F"是 Normal 被漏成正文；"表E-1"是 Heading 3 被排成小标题 | 按**角色**判定，并用正则兜底：`^附录[A-Z]` 一律一级、`^表` 一律题注 |
| **目录区被"附录A"条目截断** | 目录里的"附录A…"被当成一级标题加了分页 | 目录区用「`目录` 段 → **其后第一个 Heading 段落**」界定，不要用"第一个匹配 ^附录 的段" |
| **表头判定只看"首行"** | 附录类表格首行本是数据行（"21"/"37"/"59"），被加粗居中、还设了跨页重复 | 判据改为「首行 **且首格非纯数字** 」`not re.match(r'^[0-9０-９]+$', 首格)` |

另：
- `List Bullet` 的项目符号来自**样式内置 numPr**，只删段落上的 `numPr` 无效——须 `p.style = doc.styles['Normal']`。
- `List Number` 若要保留 "1./2./3."，就**不要**改样式，只覆盖字体／间距／缩进。
- 空段落不要删（可能承载 `sectPr`，如封面末段），只把行距设为单倍、字体设小四即可。
- 1 列表格常是"指标卡"（大号数字＋小注），统一压成五号会毁掉视觉层级 → 单列表格只统一字体族与颜色，**保留原字号**。

## 收尾

- 若本次重排本身要登记在文档内（如附录 D 增列一条"全文版式按公文格式规范化"），
  注意同步更新全稿的**项数／处数计数**与目录条目，别让不同章节互相矛盾。
- 交付：`present_files` 给出新文档；勘察／排版／校验脚本留在 `<项目>/审议过程文件/` 便于复核与重跑。
